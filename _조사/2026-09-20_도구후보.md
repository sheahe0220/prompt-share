## 1. SPOTPY  (보정)

https://github.com/thouska/spotpy   MIT

`33_루프.md` 의 캘리브레이션과 바로 맞물린다. 지금 루프 예시는 파라미터를 에이전트가
손으로 바꾸는 방식인데, SPOTPY 는 SCE-UA · DDS · MCMC 같은 정식 최적화기로 파라미터
공간을 뒤진다. 목적함수 17개(KGE · NSE 포함)와 수문 서명 함수 23개가 들어 있다.

```text
pip install spotpy       pyswmm env 에 없다
```

**루프와 역할을 가른다.** 수치 탐색은 SPOTPY 가, 탐색 범위와 건드리지 말 파라미터를
정하는 판단은 사람이, 지표 판정은 verify.py 가 한다.

`hydroeval` (KGE · NSE 계산 전용)은 2023-09 에 멈췄다. KGE 는 `33_루프.md` 에 이미
써 둔 함수로 충분하므로 깔지 않는다.

## 2. ccusage  (사용량)

https://github.com/ccusage/ccusage

Claude Code 가 남기는 로컬 기록을 읽어 토큰과 비용을 보여 준다. 올리지 않고 로컬에서
읽는다. 설치 없이 바로 돈다.

```text
npx ccusage            일별
npx ccusage monthly    월별
npx ccusage session    대화별
```

루프나 에이전트를 여럿 돌리면 어디서 토큰이 새는지 보는 데 쓴다. `33_루프.md` 의
"비용 상한" 을 재는 수단이 된다.

## 3. swmmio  (SWMM 입출력)

https://github.com/pyswmm/swmmio   MIT

pyswmm 은 모의를 돌리는 쪽이고 swmmio 는 .inp 와 .rpt 를 표로 읽고 고치는 쪽이다.
시나리오마다 .inp 를 손으로 고치거나 정규식으로 바꾸는 일이 있으면 이것으로 바꾼다.
pyswmm 과 같은 단체가 관리한다.

```text
pip install swmmio
```

**쓰기 전에 확인할 것.** `[CONTROLS]` 와 `CUSTOM` 단면처럼 우리 모형이 쓰는 절을
그대로 읽고 되쓰는지 짧게 시험한다. 되쓴 .inp 를 SWMM 이 돌리는지까지 본다.

## 4. Agentic SWMM  (SWMM 에이전트 스킬)

https://github.com/Zhonghao1995/agentic-swmm-workflow   MIT
논문: Zhang & Valeo (2026), AI for Engineering 1(1) 5. doi:10.3390/aieng1010005

스킬 19개. builder · runner · calibration · uncertainty · water-quality · plot ·
report · gis · climate · experiment-audit · modeling-memory 등.

**통째로 깔지 마라.** 이유가 셋이다.

```text
보정이 약하다      탐색이 random · LHS 뿐이다. 정식 최적화기가 없다 (예제 README 101줄)
이름이 겹친다      swmm-runner 가 SWMM_NPS 의 에이전트 이름과 같다
이미 있다          SWMM_NPS 하네스에 스킬 9개 · 에이전트 6개가 있다
```

**읽어 볼 것은 둘이다.** `swmm-experiment-audit` (모의 결과를 감사 가능하게 남기는
방식)과 `swmm-water-quality`. 우리 하네스에 없는 관점이면 거기서 규칙을 빌려
`SWMM_NPS\.claude\skills\` 에 우리 식으로 쓴다.

kLabUM/SWMM-MCP-PUB (미시간대 연구실, 별 7)도 있으나 규모가 작아 지켜보기만 한다.

## 5. K-Dense 과학 스킬

https://github.com/K-Dense-AI/scientific-agent-skills   MIT

165개 중 대부분은 생물 · 화학이다. **다 깔면 매 세션 목록에 설명 165개가 실린다.**
관련 있는 것만 골라 폴더째 `~/.claude/skills/` 에 넣는다.

```text
고를 만한 것   statistical-analysis · statsmodels · statistical-power
               scientific-writing · literature-review
               scientific-visualization · geopandas · timesfm
```

**우리 지침과 부딪히는지 먼저 본다.** 특히 scientific-writing 과 scientific-visualization
은 `13_논문.md` · `10_그림.md` 와 규칙이 겹칠 수 있다. 겹치면 우리 쪽이 우선이라고
적어 두거나 깔지 않는다.

## 6. 국내 논문 검색  (KCI · DBpia · RISS)

PhDHan88/korea-academic-mcp 가 세 곳의 공식 Open API 를 부른다. 그런데 **별 0 개,
라이선스 없음**이다. 남의 코드에 API 키를 넘기는 구조라 그대로 쓰지 않는다.

**직접 만드는 편이 낫다.** 공식 API 만 부르는 짧은 스크립트나 스킬이면 된다.
`13_논문.md` · `20_자료조사.md` 와 붙어 KCI 원고의 선행연구 조사에 쓴다.
키는 사용자가 각 기관에서 받아야 한다.

## 7. 기상청 ASOS · WAMIS 자료

```text
기상청 ASOS 시간자료   https://www.data.go.kr/data/15059218/openapi.do
WAMIS OpenAPI         http://wamis.go.kr:8080/wamisweb/rf/w4.do
```

MCP 가 몇 있으나(Koomook/data-go-mcp-servers 는 2025-09 에 멈춤, aeriis-kr/opendata-mcp
는 별 11) 강수 · 수위만 쓰면 되므로 **전용 스크립트가 낫다.** 사상 목록을 주면 강우
관측소 자료를 받아 `09_원자료` 규칙대로 쌓는 것까지 한 번에 만들 수 있다.
`RAINFALL` 폴더를 손으로 채우는 일이 있으면 가장 먼저 덜어 낼 곳이다.

## 8. Zotero MCP

https://github.com/54yyyu/zotero-mcp   MIT

이 PC 에 Zotero 가 없다. 문헌을 PDF 폴더로만 관리한다면 지금은 필요 없다. 논문을
여러 편 쓰게 되면 Zotero 로 옮기고 이것을 붙인다. DOI 로 추가, 전문 읽기, docx 에
인용 필드 넣기까지 된다.

## 9. 시계열 기초모형  (Chronos · TimesFM)

https://github.com/amazon-science/chronos-forecasting
https://github.com/google-research/timesfm

학습 없이(zero-shot) 시계열을 예측한다. 에버글레이즈 수위 예측에서 Chronos 가 여러
관측소 · 예측 시간대에서 가장 낮은 오차를 냈다는 연구가 있다 (arXiv 2508.04888).
[검색확인. 원문은 안 읽었다]

**연구 착상이다.** 대심도 터널 수위 6.2 년치가 있으므로 SWMM 모의와 나란히 대조군으로
세울 수 있다. torch 가 필요해 pyswmm env 가 아니라 별도 env 에 둔다.

## 10. paper-qa

https://github.com/Future-House/paper-qa   Apache-2.0

PDF 더미에 질문하면 인용과 함께 답한다. `09_원자료` 의 설계보고서 수백 쪽에 쓰고
싶어지지만 **보류한다.** 기본이 외부 LLM API 와 임베딩이라 발주처 자료가 밖으로
나가고, 한글 PDF 에서 쪽 번호 인용이 얼마나 정확한지 확인하지 못했다.
지금의 `22_문서분석.md` 방식(핵심어 묶기 + 원문 발췌 + 쪽 번호)이 더 안전하다.

## 하다가 새로 알게 된 것

**펌프 뒤의 유출구는 보정할 수 없다.** OUT1 · M9999 는 배수를 0.1% 만 바꿔도 KGE 가
1.0 에서 -0.07 · -0.18 로 무너졌다. 펌프가 도는 횟수가 바뀌어 응답이 계단처럼 끊긴다.
틀에 매끄러움 점검을 넣어 이런 지점에서는 멈추게 했다.

**불투수율 배수는 1.0 위로 식별되지 않는다.** 소유역 20% 가 이미 100 이라 잘린다.

**WAMIS 서버는 연속 요청을 끊는다.** 두 번 겪었다. 도구에 쉼과 재시도를 넣었다.

**정본의 피복률 합이 100 미만인 소유역 3 개** 는 0.001 ha 자리표시라 영향이 없다고 판정했다.
